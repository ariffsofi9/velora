# VELORA working instructions

- Before starting a phase, read `docs/PROJECT_STATUS.md` and `docs/ROADMAP.md`, then inspect Git status/history. Preserve unrelated work and verify checkpoint claims against code.
- Architecture: Flutter UI in `lib/screens` and `lib/widgets`; domain models/logic, workspace repositories and services in `lib/`; Firebase Auth, Firestore and Node.js callable Functions in `functions/src`. Tests live in `test/` and `functions/test/`.
- Require verified workspace context for cafe reads. Authorization depends on active, schema-valid `user_cafe_memberships/{uid}`, `cafes/{cafeId}/members/{uid}`, cafe and owner links. Never trust `users.role`, UI state or client-supplied cafe/actor IDs as authority. Fail closed; never fall back to global data.
- Trusted callables (`createWorkspace`, `createInventoryItem`, `updateInventoryItem`, `adjustInventoryStock`) derive identity from Auth and recheck membership transactionally. Admin SDK bypasses Rules: preserve backend validation. Scoped inventory and movement client writes are denied by the repository rules draft.
- Quantity changes belong to stock operations, never metadata edits. Preserve positive integer adjustment amounts, nonnegative resulting stock, optimistic versions, stable idempotency keys for unchanged retries and payload-conflict rejection. Stock changes, movement and activity audits must commit atomically with server identity/time. Preserve initial-stock audit creation and read-only Stock History.
- Do not restore legacy global inventory, inventory-record, activity, notification or AI/cache/quota access. Remaining legacy services are not security-approved workflows. AI generation, quota/cache/saved recipes and Cook Now remain disabled until separately authorized secure implementations exist.
- Use local/fake tests for routine checks (`flutter test --no-pub`; backend unit tests via `npm test` in `functions`, with installed dependencies). Never use production for tests. Rules tests clear Firestore: run only in a deliberately isolated disposable demo emulator, never the user's working emulator. Do not reset, delete, import or overwrite emulator data.
- Emulator routing requires `--dart-define=USE_FIREBASE_EMULATORS=true`; the checked-in Chrome launch configuration omits it. Verify target/project before connecting. `firebase.workspace-emulator.json` references draft rules/indexes; `firebase.json` has no Firestore deployment configuration. Do not assume deployed protections match repository files.
- No commit, push, deployment, production mutation or data migration without explicit approval. Do not install dependencies or expand scope without authorization. Report verification limits and seek manual browser results when needed.
